# Schema Validate Validates an incoming JSON payload against a configurable field schema. ## Inputs / Outputs - **Payload** — Incoming JSON object to validate - **passed** — Emitted when payload matches the schema - **failed** — Emitted when payload does not match the schema - **debug** — Formatted debug/error messages (when debug output options are enabled) ## Validation Rules 1. All **required** fields must be present in the payload with the correct type. 2. Any field in the payload that is **not declared** (neither required nor optional) causes validation failure. 3. **Optional** fields do not need to be present, but if present, must match the declared type. ### Passed output ```json { "request": { "" }, "response": { "status": "200 OK", "text": "Request schema successfully validated" } } ``` ### Failed output ```json { "response": { "error": "400 Bad Request", "text": "Incorrect request schema fields", "details": "", "expected schema": "" } } ``` ## Configuration ### Main Settings Click **Add field** to define schema fields. Each row has: - **Key** — Field name as it appears in the payload - **Type** — Expected data type: - `Text` — JavaScript string - `Date` — ISO 8601, RFC 3339, or Unix Epoch (number or digit-only string) - `Number` — JavaScript number - `Boolean` — JavaScript boolean - **Presence**: - `Required` — Field must be present and correctly typed - `Optional` — Field may be absent; if present, must be correctly typed ### Debug Configuration - **Enable component debug** — Activates debug logging - **Send Name and ID** — Includes component name and node ID in log entries - **Send debug to Debug output** — Routes debug messages to the `debug` output pin instead of console - **Send errors to Debug output** — Routes error messages to the `debug` output pin - **Timestamp (ISO 8601)** — Prepends a timestamp to each log entry - **JSON output** — Emits log entries as JSON objects instead of plain text - **Timezone** — Timezone for timestamps (default: UTC) ## Date Validation The `date` type accepts: - **ISO 8601 / RFC 3339 strings**: `2024-01-15`, `2024-01-15T10:30:00Z`, `2024-01-15T10:30:00+02:00` - **Unix Epoch as number**: `1705315800` - **Unix Epoch as digit-only string**: `"1705315800"`
