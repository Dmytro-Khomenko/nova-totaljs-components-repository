# Route [advanced] An advanced HTTP route listener component that registers an endpoint and forwards incoming request data into the flow. Extends the native Route component with per-field output control, file type validation, and structured debug output. ## Inputs / Outputs - No inputs — triggered by incoming HTTP requests - **Output** — Incoming request data (fields selected in Output Format Settings) - **debug** — Formatted debug/error messages when debug is enabled The `message.refs.controller` property holds the request controller for use by a downstream REST response component. ## Main Settings | Field | Description | |-------|-------------| | Method | HTTP method: GET, POST, PUT, PATCH, HEAD, DELETE | | Relative Listen URL | Route path relative to the proxy endpoint. Supports wildcards (`/path/*`) and dynamic segments (`/path/{id}/`). `#` is replaced with the FlowStream ID | | Continue as | Authorization filter: **Authorized** (+), **Unauthorized** (−), **Both** (no restriction) | | Request Timeout | Timeout in milliseconds | | Request Size Limit | Maximum request body size in kB | ## Uploading File Settings - **Allow uploading files** — Enables multipart/form-data file upload - **Read files to** — Converts file buffer: Keep as files, Buffer, UTF-8, ASCII, Data URI, Base64, Hex - **Allowed file formats** — Comma-separated extension whitelist (e.g. `.wav, .mp3, .mp4`). Files with unlisted extensions receive an immediate **415 Unsupported Media Type** HTTP response: ```json { "error": "Unsupported Media Type", "text": "Unsupported file format. Supported formats: .wav, .mp3, .mp4, ..." } ``` Leave the field empty to allow all file types. ## Output Format Settings Each checkbox independently adds that part of the request to the output object. Combine any combination freely: | Field | Output key | Description | |-------|------------|-------------| | Headers | `headers` | HTTP request headers | | Payload | `payload` | Parsed request body | | User | `user` | Authenticated user object | | Cookies | `cookies` | Parsed cookies | | Query arguments | `query` | URL query string parameters | | Dynamic parameters | `params` | URL path parameters (`{id}`, etc.) | When nothing is selected, all fields are sent (same as the native Route component's `all` mode). When upload is enabled, `files` is always included regardless of selection. ## Debug Configuration Same options as Schema Validate and other components in this project: - **Enable component debug** — Master switch; all debug options require this to be enabled - **Send Name and ID / Timestamp / JSON output / Timezone** — Log format options - **Send debug to Debug output** — Route INFO/DEBUG messages to the `debug` pin instead of server console - **Send errors to Debug output** — Route ERROR/WARNING messages to the `debug` pin - **Send Requests to Debug output** — When a request arrives, log its method, URL, IP, headers, query, and body - **Send Responses to Debug output** — Log the data object being dispatched to the `output` pin
