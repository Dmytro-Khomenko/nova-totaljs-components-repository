### Audio Processor Novatalks Insights component for audio preprocessing before transcription. Receives an **array** of dialog records from OpenSearch, preprocesses each audio file using `ffmpeg`, and emits one output message **per dialog** as soon as it completes — continuous semaphore-based parallelism, no batch waiting. ## Inputs / Outputs - **Input** — Array of dialog objects (from OpenSearch fetch) - **Output** — One message per processed dialog (passthrough fields + `processed` object) - **debug** — Formatted debug/error messages ## Processing For each dialog: 1. Probes audio file to detect channels and sample rate 2. Applies frequency filters (telephone profile for 8 kHz source, broadband otherwise) 3. Resamples to configured Output Sample Rate (default 16000 Hz) 4. Normalizes loudness (if enabled) 5. Writes output WAV(s) to Temporary Directory under a unique session subfolder Stereo files are split into left and right channels processed in parallel. ## Output payload ```json { "documentID": "...", "DialogID": "...", "DialogTimeStart": "...", "RecordingFile": "...", "RecordingFileBaseName": "...", "ANI": "...", "Agent": "...", "processed": { "data": { "channels": 2, "size": 2048000, "duration": 64.3, "processTime": 520 }, "audio": [ "/tmp/audioProcessor/abc123/dialog_left.wav", "/tmp/audioProcessor/abc123/dialog_right.wav" ] } } ``` ## Configuration - **Parallel Processes** — Max concurrent audio processing jobs (semaphore limit) - **Output Sample Rate** — Target Hz for resampled output (default 16000) - **Normalize** — Apply loudness normalization via ffmpeg `loudnorm` filter - **Temporary Directory** — Base path for preprocessed WAV files ## Requirements - `ffmpeg` binary must be installed on the server - npm: `fluent-ffmpeg`, `async-sema` (auto-installed via `exports.npm`)
